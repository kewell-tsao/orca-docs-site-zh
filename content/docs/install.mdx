### Homebrew (macOS)

Orca 也作为 Homebrew cask 发布，每次稳定版本发布时自动更新：

```
brew install --cask stablyai/orca/orca
```

`brew upgrade --cask stablyai/orca/orca` 会拉取新的稳定构建。务必使用完整名称：裸 `orca` 是一个无关的 Plotly cask。该 cask 追踪稳定通道——想要 RC 构建，请使用上面的 GitHub Releases 链接或下文 [更新](#updates) 描述的应用内 **检查更新** 流程。

## 首次启动

首次启动时 Orca 会：

- 请求访问你的主目录，以便添加仓库。
- 如有 `~/.claude`、`~/.codex` 和 Ghostty 终端设置，会提示你导入。
- 将你带到一个空的欢迎界面，在此添加第一个仓库。

## 更新

Orca 默认自动更新，追踪 **stable** 通道。稳定版本经过审核；**RC（release candidate）** 构建则先送达新功能，通常每日发布。

在 Linux 上，Orca 能否自行应用更新取决于你安装的是哪个包。选择之前请看 [Linux](#linux)。

RC 通道没有永久的应用内订阅方式。在 **检查更新** 上使用修饰键点击（[设置 → 通用 → 更新](/docs/settings)，或应用/帮助菜单）：

| 修饰键                                                 | 效果                                                                    |
| ------------------------------------------------------ | ----------------------------------------------------------------------- |
| **Shift+点击**                                         | 包含最新 **RC** 预发布                                                  |
| **Cmd+点击** (macOS) / **Ctrl+点击** (Windows/Linux)   | 最新 **perf** 标签的预发布                                              |
| **Option+点击** (仅 macOS)                             | 选择通过 Orca 兼容性检查的**已验证本地 macOS 构建**                     |

你仍然可以直接从 [GitHub Releases 页面](https://github.com/stablyai/orca/releases) 下载任意构建。

<Callout title="不喜欢当前的更新？">
  旧版本始终可在 [GitHub Releases
  页面](https://github.com/stablyai/orca/releases) 获取。即使你回退版本，Orca 也不会强制降级你的 worktree 数据。
</Callout>

## 平台说明

### macOS

已签名并公证。首次启动时 macOS 仍可能要求你确认——这对基于 Electron 的应用来说是正常的。

### Windows

默认 shell 可在 [设置 → 终端](/docs/settings) 下设置为 PowerShell 或 CMD。大多数用户更适合 PowerShell。

### Linux

每次发布包含三个 Linux 包——**AppImage**、**`.deb`** 和 **`.rpm`**——同时提供 x64 和 arm64。它们包含相同的应用，区别仅在于更新方式不同，因此请据此选择。

| 包类型        | 适用场景                                                  | 更新方式                                                       |
| ------------- | --------------------------------------------------------- | -------------------------------------------------------------- |
| **AppImage**  | 你希望 Orca 自行更新，就像 macOS 和 Windows 上一样         | Orca 下载并就地应用更新                                        |
| **`.deb`**    | 你在 Debian 或 Ubuntu 上用 `apt` 管理软件                  | Orca 通知你有新版本并提供安装命令                              |
| **`.rpm`**    | 你用 `dnf`、`yum` 或 `zypper` 管理软件                     | 与 `.deb` 相同                                                 |

AppImage 为每个架构提供稳定下载链接——x64 用 [`orca-linux.AppImage`](https://github.com/stablyai/orca/releases/latest/download/orca-linux.AppImage)，arm64 用 [`orca-linux-arm64.AppImage`](https://github.com/stablyai/orca/releases/latest/download/orca-linux-arm64.AppImage)——首次运行前需要 `chmod +x`，因为 GitHub release 资产不带权限位。`.deb` 和 `.rpm` 的文件名包含版本和架构，两种格式对架构的命名不同（`orca-ide_<version>_amd64.deb` 或 `_arm64.deb`；`orca-ide-<version>.x86_64.rpm` 或 `.aarch64.rpm`），因此请从 [Releases 页面](https://github.com/stablyai/orca/releases) 获取，而不要使用固定 URL。

#### 更新的工作方式

**AppImage 自行更新。** 如果希望自动更新，选择它。Orca 检测到新版本，你点击 **更新**，它就地替换 AppImage——流程与 macOS 和 Windows 相同。

**`.deb` 和 `.rpm` 不自行更新。** Orca 仍会注意到新版本并下载包，然后给你一个 **复制安装命令** 按钮。请复制而不是重新输入：Orca 将每个程序解析为受信任系统目录中的绝对路径，并对包路径加单引号，粘贴出来的内容类似这样：

```
/usr/bin/sudo /usr/bin/apt -o Binary::file::APT::Sandbox::User=root install -- '/home/you/.cache/orca-updater/pending/orca-ide_1.4.194_amd64.deb'
```

使用哪个包管理器取决于你的系统实际安装了什么：`.deb` 用 `apt`，不行则 `dpkg -i`；`.rpm` 依次尝试 `zypper`、`dnf`、`yum`，最后 `rpm -Uvh`。下载目录遵循 `XDG_CACHE_HOME` 的设置，未设置时回退到 `~/.cache`。

**运行命令前请先退出 Orca**，安装完成后再重新打开。你正在替换一个正在运行的应用的文件，包管理器无法在进程存活时安全地替换它们。Orca 刻意从不为此提升权限：安装系统包需要 root，`orca serve` 以非特权用户运行，无头机器上没有认证代理可以弹出提示。VS Code 和 Signal 在 `.deb` 上也做了同样的选择。

**发行版管理的构建不受影响。** 如果你运行的是重新打包的 Orca——比如 AUR 构建、Nix derivation——Orca 会检测到这个安装不受它能驱动的包管理器管理，于是停止提供它永远无法应用的下载。它仍会报告有新版本存在，你可以按通常的方式更新。

<Callout title="计划中：签名的 apt/yum 仓库">
  [#18086](https://github.com/stablyai/orca/issues/18086) 追踪发布签名仓库，让你的操作系统包管理器像管理其他软件一样管理 Orca 更新。目前尚未实现——当前 `.deb` 和 `.rpm` 的更新需要上文描述的手动步骤。
</Callout>

#### CLI 命令是 `orca-ide`

在 Linux 上 [Orca CLI](/docs/cli/reference) 以 **`orca-ide`** 的名称安装，而不是 `orca`。GNOME Orca——Ubuntu 和其他 GNOME 桌面默认搭载的屏幕阅读器——已经占用了 `/usr/bin/orca`，Orca 不会遮蔽它。`.deb` 和 `.rpm` 包的名称也是 `orca-ide`，原因相同。

- `.deb` 和 `.rpm` 在安装时将 `orca-ide` 加入 `PATH`，位置为 `/usr/bin/orca-ide`。
- AppImage 用户请从 [设置 → 通用 → Orca CLI](/docs/settings) 注册 CLI。这会安装 `~/.local/bin/orca-ide`。
- 在 Orca 自己的终端内，裸 `orca` 可以直接使用。Orca 在它管理的终端的 `PATH` 上放置了一个 shim，因此 agent 和其中运行的脚本使用与 macOS 和 Windows 相同的命令。
- 在无头主机上，打包的 `orca serve` 会在启动时将裸 `orca` 写入 `~/.local/bin`（除非该名称已被它不拥有的文件占用）。它在启动 _过程中_ 写入，所以这绝不是启动服务器的方式——首次启动始终使用 [`orca-ide serve`](/docs/remote-servers)。

不要用 `command -v orca` 来验证：在 GNOME 桌面上这条命令会成功并解析到屏幕阅读器。在你自己的 shell 里用 `orca-ide`，在 Orca 内部用 `orca`。如果你希望到处都用短名称且不使用屏幕阅读器，可以自行创建链接：

```
ln -s "$(command -v orca-ide)" ~/.local/bin/orca
```
