Orca 是工作树原生的。与其在一个检出上分支和暂存，不如每个任务通过 `git worktree` 获得自己的仓库磁盘副本。这就是并行代理安全的原因 —— 它们从不踩彼此的文件。

## 模型

- 每个仓库有一个 **基础引用**（通常是 `origin/main`）。
- 每个工作树有一个 **起始引用** —— 它从哪个分支出来。
- 每个工作树有自己的分支、自己的磁盘文件和自己的代理终端。
- 删除工作树会同时移除目录和分支（带确认）。如果 git 保留了本地分支因为它可能还有未合并的提交，Orca 可以提供评审步骤 —— 参见 [保留的分支](#preserved-branches)。

## 每个功能的生命周期

1. **创建** —— 任务名称、起始选择器、可选的 GitHub / Linear / Jira / GitLab 链接。
1. **工作** —— 代理终端、编辑器标签、浏览器标签、终端面板全部限定在此工作树。
1. **评审** —— 针对起始引用的差异视图、标注 AI 差异、归因。
1. **发布** —— 提交、推送、打开 PR、等待检查 —— 全部内联。
1. **归档或删除** —— 一键移除工作树和分支。

## 创建在后台运行

提交创建工作树对话框会立即关闭它 —— `git fetch` 和 `git worktree add` 工作在您继续使用 Orca 时在后台继续。新工作树出现在带有进度行的侧边栏中，工作树标签显示实时初始化状态，直到检出完成并切换到终端。您可以在创建进行中切换到其他工作树、观看进度或从标签内面板取消它。如果创建失败，面板会显示错误并带有重试按钮。

## 起始选择器

创建工作树时，您选择从哪个分支出来。这可以是：

- 仓库的基础引用（快速路径）。
- 另一个本地分支 —— 用于在评审中的 PR 之上叠加工作。
- 特定的提交 SHA。
- 现有远程分支 —— Orca 会 fetch 并检出它。

## 共享目录 & gitignore 的文件

全新的工作树是干净的检出。存在于 gitignore 路径中的依赖项、缓存和本地机密缺失，直到您重新创建它们。

Orca 以三种互补方式填补这一空白：

1. **工作树共享路径**（每个仓库，在设置 → 仓库中）—— 路径从主检出实体化到每个新工作树（macOS 上可用时 APFS 克隆复制，否则符号链接）。
1. **`orca.yaml` 中的 `worktree.sharedDirectories`** —— 仓库内提交的 **gitignore 的目录** 列表，通过链接共享（包括在 APFS 上）。用于像 `node_modules` 或 `.cache` 这样的大型可重建树。条目必须在主检出中作为目录存在 **且** 被 gitignore；已跟踪或缺失的路径被跳过。
1. **仓库根目录的 `.worktreeinclude`** —— **gitignore 的文件或目录到复制（而非符号链接）** 到每个新工作树的列表，因此每个工作树拥有自己的副本。典型条目：`.env`、`.vscode/` 下的本地配置。允许空行和 `#` 注释。目前仅支持 **字面** 路径 —— glob 和否定会被跳过并带有警告。已跟踪、缺失或未被 gitignore 的路径不会被复制。

`orca.yaml` 共享目录 **添加到** 每个用户的工作树共享路径列表；它们从不替换它。已共享/链接的路径不会从 `.worktreeinclude` 重新复制。

关于初始化脚本、默认标签、命令选择、路径规则、限制以及哪个检出提供每个设置，参见 [orca.yaml & .worktreeinclude 参考](/docs/model/orca-yaml)。

```yaml
# orca.yaml (仓库根目录)
worktree:
  sharedDirectories:
    - node_modules
    - .cache
```

```text
# .worktreeinclude (仓库根目录)
.env
.env.local
.vscode/settings.json
```

## 创建对话框：项目、在...上运行、代理和任务链接

创建工作空间对话框对 **项目** 和 **在...上运行** 使用自动完成下拉菜单：

- 键入进行筛选；Enter 提交选定行。
- **项目** 始终将 **添加新项目** 固定在底部 —— 当安装还没有项目时，创建永远不会陷入死胡同。
- **在...上运行** 列出就绪的主机和 recipe，以及在该机器上仍需项目初始化的主机。在需要初始化的主机上，选择 **设置项目位置** 而不离开创建表单，然后浏览到现有检出/文件夹或在该主机上克隆 Git 仓库。Orca 选择新就绪的位置，因此您可以继续创建工作树。断开连接的 SSH / 远程主机可以提供 **连接** 而不将它们选为运行目标。**添加主机** 为 SSH 或远程 Orca 服务器目标保持固定。
- **代理** 选择器（折叠或展开）可以 **设为默认** 您在创建时选择的代理，包括空白终端。
- 从名称字段链接 GitHub PR、Linear issue、GitLab MR 或 **Jira** issue（粘贴 Jira URL 或在 **Jira** 模式下搜索）。链接的 issue 出现在工作树卡片上。参见 [Jira 项抽屉](/docs/review/jira)。

参见 [运行 Orca 的方式](/docs/ways-to-run)。

## 表情符号工作空间名称

在工作空间名称字段中，您可以键入 Slack 风格的短代码（`:rocket:`）并从短代码建议弹出窗口中选择。相同的选择器在您双击重命名工作树、在 **编辑工作树详情** 中编辑它，或在 [工作树跳转面板](/docs/model/quick-open) (`Cmd-J`) 中键入短代码时使用。显示名称保留表情；当 Orca 派生 git 分支名称时，它将已知表情重写为可读的短代码（例如 🚀 → `rocket`）。跳转面板搜索通过该短代码派生片段匹配表情符号命名的工作空间。

## 命名分支

默认情况下 Orca 从您键入的工作空间名称派生新工作树的分支名称，或从链接的 GitHub PR、Linear/Jira issue 或 GitLab MR 派生（当工作空间从其中一个创建时）。要改为设置显式分支名称，在创建工作树对话框中展开 **高级** 抽屉并在 **分支名称** 字段中键入（占位符 `feature/my-branch`）。

同一个抽屉让您可以从与新工作空间相同的仓库中选择活动工作树作为 **父工作空间**。这仅在 Orca 的侧边栏中嵌套工作空间；它不改变 Git 历史或分支。Orca 排除已归档的工作空间和会创建循环的选择。

当从 **Linear issue** 创建时，Orca 使用 Linear 为该 issue 自己的分支名称（当 Linear 提供时）作为分支覆盖 —— 与 Linear 在其 UI 中建议的名称相同 —— 而不是仅将 issue 标题转换为短横线形式。

分支名称字段仅在您从键入的工作空间名称或基础分支创建时提供。当工作空间绑定到已跟踪的工作项时，分支从该项派生 —— 链接的 GitHub PR 甚至会在提交时重新解析分支 —— 因此 Orca 隐藏该字段以避免静默忽略覆盖。

## 侧边栏布局

侧边栏默认按 **项目** 分组工作树 —— 顶层行是项目（一个项目 = 一个 git 仓库或相关集群），展开为您正在积极工作的工作树。头部有自己的筛选输入（与全局搜索分开），因此您可以在不离开侧边栏的情况下缩小列表范围。

侧边栏头部筛选菜单在共享的 **显示** 部分下分组主机和项目作用域（**主机** 和项目的子菜单项），然后是隐藏切换：

- **休眠** 工作空间 —— 当其他工作树被过滤时，每个项目的 **入口点 / 主** 工作空间在此筛选器下保持可见，因此项目行不会在该检出空闲时消失
- **默认分支除外**（仅在 **隐藏休眠** 开启时）—— 在休眠扫描期间保持默认分支工作空间可见；当休眠工作空间已显示时，该子选项被隐藏
- **默认分支** 工作空间（主检出行）
- **自动化任务创建的** 工作空间
- **CLI 创建的** 工作空间 —— 通过 `orca worktree create` 创建（悬停卡片查看 **Orca CLI** 来源详情）
- **其他客户端的** 工作空间 —— 当共享的 [远程 Orca 服务器](/docs/remote-servers) 有从另一个已配对客户端创建的工作空间时，**隐藏其他客户端的工作空间** 出现；打开它将此设备的列表限制为您在此处创建的工作空间。空的 `Cmd-J` 最近项和数字快捷键遵循相同筛选；键入查询仍能找到隐藏行。
- **分离 HEAD** 工作空间 —— 坐在提交而非分支上的检出

活动筛选计数显示在筛选控件上；**清除** 仅重置打开的筛选。文本搜索和 [工作树跳转面板](/docs/model/quick-open) (`Cmd-J`) 在您键入查询后仍能到达仅被隐藏切换隐藏的工作空间。Cmd-J 打开时保持侧边栏的主机和项目作用域；按 **Tab** 调整其临时主机和单个仓库筛选。

当您添加包含多个 Git 仓库的父文件夹时，Orca 可以单独导入选定的仓库，或将它们分组在一个项目组下。

顶部的 **搜索** 按钮打开 [工作树跳转面板](/docs/model/quick-open) (`Cmd-J`) —— 相同的界面，面向不依赖键盘进行导航的用户点击驱动。状态栏内联显示代理活动；未读工作树加粗而非徽章。

您可以将工作树固定在其项目顶部以保持长时间运行的工作可见，右键点击工作树暴露归档 / 休眠 / 删除操作。要从键盘开始删除，悬停工作树或文件夹工作空间，在 macOS 上按 `Cmd-Shift-Backspace` 或在 Windows / Linux 上按 `Ctrl-Shift-Backspace`；正常确认对话框仍会出现。在点击时按住 `Cmd`（Linux/Windows 上 `Ctrl`）将工作树添加到多选，或按住 `Shift` 选择连续范围 —— 右键点击任何选定的工作树将操作应用于选择中的每个工作树。仓库行本身可以通过拖动重新排序。

当工作树有嵌套的子工作树（例如来自编排或带父级的 `worktree create`）时，上下文菜单中的 **休眠** 变成带有 **此工作空间** 和 **包含后代 (N)** 的子菜单，**包含后代删除…** 在其确认对话框中列出后代之前明确删除作用域。包含后代休眠会在同一项目、仓库和主机上关闭选定工作空间和每个经过验证的嵌套子级的活动面板 —— 仅目标有活动终端或浏览器标签的工作空间。删除父级会使现有级联删除显式。陈旧的血缘链接、循环以及跨主机或仓库边界的子级被排除。

父工作树在 **N 个子项** 标签下显示其嵌套子项；点击标签显示或隐藏它们。从键盘做相同操作，在 [设置 → 快捷键](/docs/settings) 下分配 **切换子工作空间**。它作用于指针下方的工作树，或未悬停时的活动工作树，完全执行该卡片标签所做的操作。在没有自己标签的卡片上（它没有子项，或侧边栏筛选隐藏了所有子项），它使用卡片父级上的标签，如果没有则什么也不做。

双击侧边栏中的工作树标题进行内联重命名。双击卡片上其他位置仍会打开完整编辑对话框。在 **编辑工作树详情** 中，issue 字段接受 **GitHub** 或 **Linear**（字段上有标签；粘贴 URL 自动检测）。每个工作空间一个链接的 issue —— 更改提供商或清除字段会取消链接上一个。对于主机断开的 SSH 工作空间，卡片标题行可以显示内联重新连接控件（参见 [SSH 工作树](/docs/ssh)）。

## 资源管理器清理

当您需要在删除前审查设置中的工作空间时，使用 **资源管理器 → 清理工作空间**。列表包括本地工作树、主工作树、文件夹工作空间以及断开连接的 SSH 主机上的工作空间。搜索、筛选或排序列表以检查每个工作空间的状态、最近活动、大小、Git 状态和链接的评审，然后再选择删除。

## 保留的分支

批量删除工作空间（侧边栏多选或资源管理器清理）仍会移除磁盘文件夹。如果 git 拒绝删除本地分支因为它可能包含未合并的提交，Orca 会保留这些分支并显示诸如 **评审 N 个分支** 的提示。打开它列出保留的分支，您可以强制删除一些并保留其他。未选择的分支留在仓库中；工作空间文件夹不会被恢复。

## 多仓库项目组 & 文件夹工作空间

当您导入包含多个 Git 仓库的父文件夹时，Orca 可以在侧边栏的单个 **项目组** 下分组这些仓库。每个项目组暴露一个 **文件夹工作空间** 流程 —— 一个类似工作树的条目，位于父文件夹级别并将其任务源绑定到下面的一个仓库，因此一个功能的 GitHub/GitLab/Linear/Jira 任务表面保持附加到正确的仓库，即使工作空间本身与其兄弟在侧边栏中分组。

要创建一个，在侧边栏中悬停项目组的标题行并点击 **+** 操作（提示："为 _组_ 创建工作空间"）。编辑器对话框（"创建文件夹工作空间"）让您为工作空间的任务源选择源项目、命名工作空间，并可选附加链接的 issue 或 PR。提交后，文件夹工作空间出现在项目组下面，与常规仓库作用域的工作树并排。

删除项目组时，Orca 还提供一个复选框以在同一操作中删除组包含的项目（底层的仓库注册）—— 因此不再使用的集群的清理是一次确认，而非几次。

## 使用原生 git

每个 Orca 工作树都是真正的 git 工作树。您可以在其中打开终端并使用 `git status`、`git rebase`、`git cherry-pick` 以及其他任何命令 —— Orca 会在下次渲染时获取更改。

您自己用 `git worktree add` 创建的工作树保持外部状态，直到您在 Orca 中显示它们。如果仓库隐藏了它们，侧边栏会显示一个 **隐藏的工作树** 卡片。点击它打开 **非 Orca 工作树**，然后选择要在侧边栏中显示的工作树的 **显示**。

在 **设置 → 通用 → 工作空间** 中，为外部工作树源设置全局默认值：Claude Code 工作树、GSD 工作树、其他位置，以及您添加的任何自定义绝对路径位置。这些默认值适用于该主机上当前和未来的工作树；新的全局自定义根目录默认隐藏。在项目的 **非 Orca 工作树** 对话框中，您可以覆盖该项目的源或返回全局设置，然后搜索和恢复单个隐藏的工作树。

<Callout>
  如果您从 CLI 执行 `git worktree remove`，Orca 会在下一次刷新该仓库时
  注意到并清理其自己的状态。
</Callout>
