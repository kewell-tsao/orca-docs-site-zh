当您关闭 Orca 时，下次启动会重新水合整个工作空间：每个打开的工作树、每个终端分屏、每个面板的滚动缓冲区，以及您聚焦的标签。您不应该需要记住您在哪个分支上运行了哪些代理 —— 那是 Orca 的工作。

## 恢复的内容

- **打开的工作树** —— 侧边栏中您打开的每个工作树。
- **标签和分屏** —— 每个工作树的面板布局，包括嵌套分屏和聚焦的标签。
- **正在运行的代理进程** —— 您运行的代理在 Orca 退出期间保持运行。后台守护进程拥有 PTY，因此关闭应用窗口不会在中途杀死 Claude Code、Codex 或任何其他代理 CLI。下次启动时，Orca 会热重新附加到相同进程。要改为结束它们，请使用 **完全退出**（参见 [恢复何时运行](#when-restore-runs)）。
- **终端滚动缓冲区** —— 每个终端的缓冲区，包括 Orca 关闭时产生的输出。
- **聚焦的工作树和标签** —— Orca 打开到您关闭时的同一视图。

## 不恢复的内容

守护进程随主机一起消亡，因此任何让整个机器停机的操作 —— 重启、OS 更新、内核恐慌、硬关机 —— 都会结束每个正在运行的代理。下次启动时，工作树、标签、分屏和上次已知的滚动缓冲区会回来，但代理进程本身没了。在任何标签中重新运行代理即可继续。

Orca 关闭时守护进程崩溃对它持有的会话有相同效果，但下次启动时布局和滚动缓冲区仍会恢复。

## 恢复何时运行

会话恢复在每次启动时运行。回来的内容取决于 **守护进程** 及其会话在 Orca 退出和关闭期间发生了什么：

**守护进程存活 → 代理保持运行：**

- **Cmd-Q** —— 正常退出方式。代理在后台继续工作。
- **自动更新重启** —— Orca 重启以安装更新；代理不受影响。
- **应用崩溃** —— 如果 Orca 本身崩溃，守护进程会为下次启动的热重新附加保持您的会话存活。

**守护进程死亡 → 代理消失，布局仍恢复：**

- **主机重启** —— 笔记本重启、OS 更新、内核恐慌、硬关机。下次启动时，工作树、标签、分屏和最后持久化的滚动缓冲区仍会回来。

**退出前会话停止 → 代理和终端标签消失：**

- **完全退出** —— 您确认后，Orca 关闭每个终端标签并停止其会话，就像 **设置 → 终端 → 管理会话 → 结束所有会话** 一样，然后退出。项目和工作树保留在侧边栏；关闭的终端标签下次启动不会回来。

该选项在 macOS 的 Orca 菜单中，以及 Windows 和 Linux 上应用菜单（标题栏中的 **···** 按钮）的 **文件** 下。它也在 macOS 的菜单栏图标菜单和 Windows 的托盘图标菜单中。远程主机上的终端会话可能继续在那里运行，已配对 Orca 服务器的标签如果服务器从未收到关闭可能会回来。如果此计算机上的会话无法停止，Orca 会显示错误并保持打开。

<Callout title="全新开始">
  如果您想要干净的起点，请在退出前显式关闭工作树。没有"在新
  会话中打开"模式 —— Orca 始终恢复。已关闭的工作树保持关闭。
</Callout>
