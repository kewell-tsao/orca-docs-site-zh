一旦您有超过几个工作树，导航就会成为瓶颈。Orca 附带两个键盘优先的导航工具。

## 快速打开 (Cmd-P)

限定在当前工作树内的文件搜索。键入片段；Orca 按最近性加上匹配分数排序，并在新的编辑器标签中打开文件。结果行以 **文件名** 开头，在空间紧张时截断父目录（悬停查看完整路径）。Gitignored 文件也包含在结果中 —— 它们在已跟踪匹配之后作为第二阶段显示，因此您频繁快速打开的文件（构建输出、环境文件）保持可达，而不会污染列表顶部。

## 新标签全能框

标签条 **+** 全能框在一个字段中搜索 **打开的标签**、文件、URL 和代理（占位符：_搜索打开的标签、文件、URL、代理…_）。文件行使用与快速打开相同的文件名优先布局。匹配已打开的编辑器标签时优先使用该标签，而不是重复的文件结果，因此您跳到打开的缓冲区而不是打开第二份副本。

改为键入网页搜索而非路径或 URL，以在工作树浏览器中用您的 [默认搜索引擎](/docs/settings) 打开它。单个令牌仍优先排序文件匹配；多词短语提升搜索行。查询前缀 `?` 跳过文件和标签匹配，立即搜索。

## 工作树跳转面板 (Cmd-J)

在一次搜索中跨工作树和标签跳转。面板以侧边栏当前的主机和项目作用域打开，包括单独的仓库选择。空输入中的占位符显示 _仓库/工作树_ —— 键入任一半，Orca 相应筛选。键入仍能找到被侧边栏其他可见性切换隐藏的未归档工作树，但保持该主机和仓库作用域。Slack 风格的表情符号短代码（`:rocket:`）使用与工作空间命名相同的建议弹出窗口。

在面板中按 **Tab** 进入主机和项目筛选菜单。项目选择是仓库粒度。选定的主机和仓库缩小结果集，显示为可逐个移除的标签。更改是临时的：关闭面板会丢弃它们，下次打开会从侧边栏重新初始化筛选器。

结果包括：

- **最近聊天 & 终端** —— 空查询时，最多六个按活动排序的最近代理/终端会话（需要您的排第一，然后是已完成，然后是空闲）。您正在查看的空闲标签会被省略，因此列表保持可操作；当前标签在正在工作、等待您或有未读活动时仍会出现。行使用与标签条相同的实时注意力徽章（旋转动画、问号、铃铛、勾）。数字快捷键（macOS 上 `Cmd-1`–`Cmd-6`，Windows / Linux 上 `Ctrl-1`–`Ctrl-6`）直接跳到这些行；成员资格和顺序在面板打开时冻结，因此行不会在光标下洗牌。
- **最近工作树** —— 下一个空查询部分，按上次聚焦排序，限制数量以便列表保持可扫描。
- 项目和仓库组，因此您可以按名称跳到侧边栏部分。
- 一旦开始键入，按仓库分组的每个工作树。
- 按缓存的 GitHub PR 标题或编号（`#123`）以及缓存的 GitLab 合并请求标题或编号（`!123`）匹配的工作树，当该评审元数据已可用时。
- 每个打开的标签，先按当前工作树限定，然后全局。标签标题或内容中的匹配优先于仅在工作树、分支或仓库中的匹配；同等强度的匹配优先选择您最近使用的标签。当 Orca 有数据时，行显示最后活动的存活时长。像 `terminal` 或 `simulator` 这样的类型别名仍能匹配这些标签类型，而不会杂乱行标签。

当键入查询同时匹配 **打开的标签** 和 **工作树** 时，面板会插入每个部分的简短预览，因此两个主列表都不会被埋。如果某个部分有更多匹配，请点击其 _N more_ 行中的 **查看更多** 以每次显示 20 个额外条目。更改查询会重置展开的部分。单部分结果保持完整的硬限制列表。

当查询不匹配现有工作树时，面板提供使用键入文本作为名称的 **创建工作树** 行。现有匹配保持首先被选中，因此当真实结果可用时按 Enter 仍会跳转。

<Callout>快捷键绑定可在 [设置 → 快捷键](/docs/settings) 下重新映射。</Callout>
