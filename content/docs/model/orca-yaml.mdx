将 `orca.yaml` 和 `.worktreeinclude` 放在仓库根目录。`orca.yaml` 提供项目默认值；`.worktreeinclude` 列出要带入新工作树的忽略文件。提交这些配置文件，以便其他用户可以使用相同的规则。将机密保存在它们引用的忽略文件中。

本参考涵盖 **本地 Git 工作树**。[文件夹工作空间](/docs/model/worktrees#multi-repo-project-groups--folder-workspaces) 不创建 Git 检出或运行这些复制/共享步骤。对于其他执行目标，请参见 [运行 Orca 的方式](/docs/ways-to-run)。

## 示例

对于使用 pnpm 的项目，这会在初始化期间安装依赖项，并打开一个代理标签和一个 Git 状态标签：

```yaml
scripts:
  setup: |
    pnpm install
  archive: |
    echo Workspace archived
setupAgentStartupPolicy: wait-for-setup
defaultTabs:
  - title: Agent
  - title: Git status
    command: git status --short
worktree:
  sharedDirectories:
    - .cache
```

`.cache` 目录必须已在主检出中存在且被 gitignore。第一个标签故意没有命令：当桌面创建编辑器启动代理时，其启动优先于第一个标签的配置命令。

## 接受的键和默认值

所有键都是可选的。脚本、标题、命令和路径值必须是字符串；Orca 会修剪它们并丢弃空或超大值。无效的字段被跳过，而有效的同级字段仍会应用。未知键不配置额外行为。

| 键                          | 接受的值                                                                                                                                                                                        | 省略时                                                                      |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `scripts.setup`              | 非空脚本字符串，包括 YAML 块标量（`\|`）。在启用初始化时在新工作树中运行。                                                                                                                         | 无项目初始化脚本。                                                          |
| `scripts.archive`            | 非空脚本字符串。在启用钩子时，归档/删除前在工作树中运行。                                                                                                                                           | 无项目归档脚本。                                                            |
| `setupAgentStartupPolicy`    | 确切为 `start-immediately` 或 `wait-for-setup`。                                                                                                                                                      | `start-immediately`；本地 **等待** 设置仍优先。                             |
| `issueCommand`               | 用于创建编辑器中链接的 GitHub/GitLab 项的非空命令模板。                                                                                                                                          | 无项目模板；编辑器仍可提供其内置代理提示。                                  |
| `defaultTabs`                | 带有可选 `title`、`command` 和 `color` 的映射列表。每个条目至少需要一个有效字段。`color` 接受 `#RGB` 或 `#RRGGBB`。                                                                                  | 正常初始终端行为。                                                           |
| `worktree.sharedDirectories` | 仓库相对目录路径列表。仅共享存在且被 gitignore 的目录。                                                                                                                                           | 仅应用用户设置的共享路径。                                                  |
| `environmentRecipes`         | 每个工作空间的环境 recipe 列表。参见 [Cloud VM](/docs/ways-to-run#4-cloud-vms-per-workspace-environments) 和 `orca-per-workspace-env` 技能，了解 recipe 字段和生命周期命令。 | 无项目 recipe。                                                             |

`scripts` 和 `worktree` 必须是映射；`defaultTabs`、`environmentRecipes` 和 `sharedDirectories` 必须是列表。`setupRunPolicy` 和 `commandSourcePolicy` 是 **设置值**，不是 `orca.yaml` 接受的键。

### 解析失败和限制

**无效 YAML 或任何位置的重复映射键会拒绝整个文件。** Orca 不保留最后一个重复值。非映射根、过多别名展开或超大文件也不会产生配置。接受重复键的 YAML 检查器不代表 Orca 会接受该文件。

| 限制                                                                                                     | 超出时的结果                                                                                          |
| --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 整个文件：256 KiB (262,144 UTF-8 字节) **且** 262,144 UTF-16 代码单元                               | 整个文件被拒绝。                                                                                          |
| 每个字符串字段：64 KiB (65,536 UTF-8 字节) **且** 65,536 UTF-16 代码单元，修剪前测量 | 字段被丢弃。                                                                                                |
| `defaultTabs`：256 个输入条目                                                                          | 整个标签列表被丢弃。                                                                                      |
| `environmentRecipes`：256 个输入条目                                                                   | 整个 recipe 列表被丢弃，并带有 recipe 诊断。                                                         |
| `worktree.sharedDirectories`：前 100 个输入条目                                                     | 后面的条目被忽略，即使前面的条目无效或重复。                                                    |
| YAML 别名展开：解析器 `maxAliasCount` 为 100                                                       | 如果解析器的展开预算超出，整个文件被拒绝；这不是别名令牌的简单计数。 |

## 哪个检出提供配置？

**主检出** 是 Orca 中注册的仓库文件夹。它可能在与新工作树不同的分支上。

| 配置                                         | 从哪里读取                                                                                    |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 初始化脚本、初始化启动策略和 `defaultTabs` | **新工作树的** `orca.yaml`。                                                          |
| 共享目录规则及其源目录   | **主检出的** `orca.yaml` 和文件系统。                                       |
| 复制规则及其源文件                     | **主检出的** `.worktreeinclude` 和文件系统。                                |
| 归档脚本                                        | **主检出的** `orca.yaml`，以工作树作为其工作目录执行。 |
| Issue 命令                                         | **主检出的** `.orca/issue-command`，然后是其 `orca.yaml`。                      |

更改功能分支的 `.worktreeinclude` 或共享目录列表不会更新主检出。创建另一个工作树之前，请确保主检出具有预期的规则和忽略的源路径。初始化和标签默认值遵循新工作树中检出的修订。这些默认值在创建期间应用；它们不会同步现有标签或文件。

## 初始化、归档和命令选择

在 **设置 → 仓库** 中，初始化可以自动运行、每次询问或默认跳过。新仓库默认为运行初始化。[CLI](/docs/cli/reference#worktrees) 接受 `--setup run|skip|inherit`；`inherit` 遵循该设置策略。有效的文件不会绕过 Orca 的命令批准。

**命令源 & orca.yaml** 控制初始化和归档脚本：

| 设置选择                    | 使用的脚本                                    |
| ---------------------------------- | ----------------------------------------------- |
| **仅 orca.yaml** (`shared-only`) | 仅 YAML 钩子；本地钩子被忽略。    |
| **仅本地** (`local-only`)      | 仅本地钩子；YAML 钩子被忽略。  |
| **运行两者** (`run-both`)          | 先 YAML，后本地，合并为一个脚本。 |

当没有保存源选择时，非空的本地钩子为该钩子选择 **仅本地**；否则 Orca 使用 **仅 orca.yaml**。共享目录与此命令源选择无关。

初始化在 **初始化** 终端中运行。在 macOS/Linux 上，Orca 编写带有 `set -e` 的 Bash 运行器；前导 `#!` 行上支持的 shell 选项被重放。在原生 Windows 上，运行器使用 `.cmd` 语法并调用每个非空行，在失败时停止。前导 POSIX shell `#!` 行仅在 Git Bash 已配置且可用时才选择 Bash；否则 `.cmd` 运行器在运行任何命令之前拒绝脚本。选择 PowerShell 作为终端不会将初始化脚本变成 PowerShell 代码。

初始化运行器接收：

| 变量                                  | 值                                                             |
| ----------------------------------------- | ----------------------------------------------------------------- |
| `ORCA_ROOT_PATH`                          | 主检出路径。                                            |
| `ORCA_WORKTREE_PATH`                      | 新工作树路径。                                                |
| `ORCA_WORKSPACE_NAME`                     | 工作树目录基本名称，而非重命名的显示标题。 |
| `CONDUCTOR_ROOT_PATH`, `GHOSTX_ROOT_PATH` | `ORCA_ROOT_PATH` 的兼容性别名。                       |

路径和 shell 语法因平台而异。在 Bash 中使用 `$ORCA_WORKTREE_PATH`，在 `.cmd` 脚本中使用 `%ORCA_WORKTREE_PATH%`。`wait-for-setup` 在代理启动前等待成功的初始化；YAML 或本地等待设置启用它。这控制启动顺序，而非是否运行初始化。

归档钩子在本地删除前运行；CLI 需要 `--run-hooks` 启用它们。失败的归档钩子会阻止删除，除非调用方显式接受该失败。

### 终端默认值和 issue 命令

`defaultTabs` 为新工作树创建终端标签一次。命令被跳过时，标题和颜色仍然适用。标签命令遵循初始化运行决策，被 **仅本地** 抑制（使用初始化命令源策略）。

在 **桌面创建编辑器** 中，代理/启动命令占据第一个模板标签，因此 **第一个标签的模板命令不会运行**。为代理保留该标签，将其他命令放在后面的标签中。使用 `--agent` 的本地 CLI 创建会在配置的标签旁边创建一个单独的启动终端；每个允许的模板命令都可以运行。标签命令不等待初始化完成，因此需要已安装依赖项的命令应在初始化完成后运行。示例的 Git 状态命令不依赖安装。

`issueCommand` 有自己的覆盖：非空的 `.orca/issue-command` 内容优先于 YAML。清除该本地文件会恢复共享模板。这与初始化/归档命令源选择是分开的。模板支持 `{{artifact_url}}` 表示链接项的 URL，旧版 `{{issue}}` 表示其编号；编辑器决定是否使用模板。共享 YAML 命令使用 Orca 的批准流程，可以重用已保存的信任；本地覆盖被视为用户编写，不触发共享命令提示。

```yaml
issueCommand: |
  echo "Linked item: {{artifact_url}}"
```

## 共享 vs 复制忽略路径

所有三种机制都采用相对于主检出的路径，并保留现有目标。先应用设置路径，然后是 YAML 共享目录，最后是 include 复制。已通过共享存在的路径不会再次复制。

| 机制                                         | 源条目                                                                                  | 在新本地工作树中的结果                                                                                                                  |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **设置 → 仓库 → 工作树共享路径** | 个人仓库设置；现有文件或目录。                                     | macOS 上可用时 APFS 克隆复制；否则链接。克隆有独立内容，链接共享编辑。                         |
| `worktree.sharedDirectories`                      | 主 `orca.yaml` 中列出的现有、**gitignore 的目录**。添加到设置路径。 | 始终是主目录的链接，包括在 APFS 上。Windows 在符号链接之前尝试目录联接。编辑影响共享源。 |
| `.worktreeinclude`                                | 主检出中列出的现有、**gitignore 的文件或目录**。                   | 私有副本，可用时使用 APFS 克隆复制，否则普通复制。从不回退到共享链接。                        |

YAML 共享路径将反斜杠规范化为 `/`，移除前导 `./` 和尾随 `/`，并去重。拒绝绝对路径、驱动器前缀路径、空路径段、`.`/`..` 段以及任何 `.git` 段。文件、缺失目录或未忽略的目录被跳过。

### .worktreeinclude 格式和复制预算

```text
# .worktreeinclude
.env
.env.local
.vscode/settings.json
```

使用 **每行一个字面路径**，锚定到仓库根目录。空行和以 `#` 开头的行被忽略；内联注释不会被去除。反斜杠、前导 `./` 和尾随 `/` 被规范化，重复项被移除。包含 `*` 或 `?` 的 glob 模式和以 `!` 开头的否定模式被跳过。使用不带遍历或 `.git` 的相对路径；仅复制存在且被 gitignore 的条目。include 文件必须是常规文件且不大于 256 KiB；Orca 最多考虑 1,000 个有效的字面路径候选。

普通 include 复制限制为 **每个新工作树总计 2 GiB 文件字节和 50,000 个文件系统条目**，复制前测量。APFS 克隆不消耗字节预算，但仍消耗条目预算；回退到普通复制必须符合字节预算。超出剩余预算的条目被跳过，创建报告警告。较早被拒绝的条目也可能耗尽受限的大小遍历，导致后面的条目未被测量。这些是准入限制，不是对复制期间文件增长的配额。

复制顶层源符号链接使用其目标的内容。嵌套符号链接保持为链接，因此通过一个编辑仍可能影响其引用。大型依赖树通常应属于初始化或有意共享，而非 `.worktreeinclude`。

## 当配置看起来不起作用时

1. 从上面的表检查正确的检出、确切的键拼写、值类型、重复键和限制。解析失败可以同时禁用初始化、标签和共享目录。
1. 检查初始化的运行策略、命令源选择、批准和第一个标签启动行为。`--setup run` 更改运行决策；它不覆盖 **仅本地**。
1. 检查源路径是否在主检出中存在，以及 `sharedDirectories` 是否为目录。在那里用 `git check-ignore -- path/to/entry` 验证忽略状态；已跟踪或未忽略的路径不符合 YAML 共享或 include 复制的条件。
1. 检查现有目标或复制预算警告。缺失的共享目录被跳过而不警告；并非每个跳过的字段/路径都有可见错误。没有警告不代表被接受。

关于创建流程，参见 [工作树](/docs/model/worktrees#shared-directories--gitignored-files)；关于仓库偏好，参见 [设置](/docs/settings#repository)。
