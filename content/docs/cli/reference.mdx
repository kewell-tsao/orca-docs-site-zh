`orca` CLI 与正在运行的 Orca 运行时通信。当 shell 脚本或代理需要检查工作树、启动终端、打开文件、自动化内置浏览器或向 Orca 报告进度时使用它。

## 验证运行时

在 [设置 → 通用 → Orca CLI](/docs/settings) 下注册 CLI，然后检查它是否能连接到 Orca。

<Callout title="在 Linux 上命令为 orca-ide">
  GNOME Orca —— 大多数 GNOME 桌面附带的屏幕阅读器 —— 已占用 `/usr/bin/orca`，
  因此 Orca 的 Linux CLI 安装为 `orca-ide`。不要用 `command -v orca` 检查它：在
  GNOME 桌面上该命令会成功执行，但会指向屏幕阅读器而非 Orca。本页面统一使用
  `orca` —— 在 Linux 上请理解为 `orca-ide`。参见 [安装 → Linux](/docs/install#linux)。
</Callout>

在 macOS 和 Windows 上：

```bash
command -v orca
orca status --json
```

在 Linux 上：

```bash
command -v orca-ide
orca-ide status --json
```

如果 Orca 尚未运行：

```bash
orca open --json
orca status --json
```

`orca open` 在不抢占您正在使用的应用键盘焦点的情况下启动 Orca。如果 Orca 窗口已打开，它什么也不做。

当其他工具需要解析结果时，使用 `--json`。人类可读的输出用于快速终端检查。

## 选择器

大多数命令接受选择器，而不是要求使用长 ID：

```bash
orca repo show --repo id:<repoId> --json
orca worktree show --worktree active --json
orca worktree show --worktree path:/abs/path/to/worktree --json
orca worktree show --worktree branch:feature-name --json
orca worktree show --worktree issue:123 --json
```

`active` 和 `current` 从 shell 的当前目录或终端上下文解析为封闭的 Orca 管理工作树。在可能在目标工作树外运行的脚本中使用显式选择器。对于远程运行时，首选完整的服务器端选择器，例如 `id:<repoId>::<absolute-worktree-path>` 或 `path:<absolute-server-path>`，因为本地 shell 的当前目录可能在运行时主机上不存在。

## 选择主机

列出当前 Orca 主机可以目标的每台机器以及每个的选择器：

```bash
orca host list --json
```

结果包括本机、其已注册的 [SSH 目标](/docs/ssh) 和已配对的 [远程 Orca 服务器](/docs/remote-servers)。对本机使用 `--host local`，对 SSH 目标使用 `--host ssh:<target-id>`，对已配对服务器使用 `--environment <server-name>`。SSH 行在目标连接后包含检测到的远程平台（`linux`、`darwin` 或 `win32`）；较旧或断开连接的目标报告 `platform unknown`。它们还包含 `connected` 以及已知的 SSH 生命周期 `connectionStatus`。如果在错误的选择器上放置了机器名称，Orca 会报告匹配的机器以及应使用的标志，而不是返回空结果。

`--host` 也接受 `name` 列中显示的裸名称，在任一维度上 —— `--host trader-local` 与 `--host ssh:ssh-1783599077486-fyasux` 指向同一台机器。名称仅在唯一时解析：由两个 SSH 目标、两个已配对服务器或两者都持有的名称会被拒绝，错误会返回每个候选的 id 形式 —— SSH 目标使用 `--host ssh:<target-id>`，已配对服务器使用 `--host runtime:<environment-id>`。使用它们来解决问题，因为 `--environment <server-name>` 无法分离共享名称的两台服务器。

使用 `orca host list` 打印的 id 移除已保存的 SSH 目标：

```bash
orca host rm --host ssh:<target-id> --json
```

它以与设置相同的方式移除目标，因此被动的 `~/.ssh/config` 导入不会在下次启动时重新添加别名。它只接受 `ssh:<target-id>` 形式，而不是裸名称，因为它删除数据。它拒绝 `--host local`、已配对服务器（使用 `orca environment rm`）以及此 Orca 主机没有的 id。

## 运行时命令

```bash
orca open --json
orca status --json
orca serve --port 6768 --bind 100.64.1.20 --pairing-address 100.64.1.20 --json
```

`orca serve` 在前台启动运行时服务器而不打开桌面窗口。将其用于 [远程 Orca 服务器](/docs/remote-servers) 或无头环境，并用 `Ctrl-C` 停止它。它接受来自 localhost、LAN 和 Tailscale 地址的客户端；添加 `--allow-public` 也接受公共互联网地址。
使用 `--bind <literal-ip>` 选择监听接口；`--pairing-address` 更改向客户端通告的地址。

## 仓库

```bash
orca repo list --json
orca repo add --path /abs/path/to/repo --json
orca repo add --path /abs/path/to/folder --kind folder --json
orca repo show --repo id:<repoId> --json
orca repo set-base-ref --repo id:<repoId> --ref origin/main --json
orca repo search-refs --repo id:<repoId> --query main --limit 10 --json
orca repo hide --repo id:<repoId> --json
orca repo unhide --repo id:<repoId> --json
```

在创建大量工作树之前设置仓库基础引用，以便新任务默认从正确的位置分支。

`repo hide` 将项目从侧边栏、项目选择器和工作空间切换器中取出，而不停止任何内容：其终端、代理和自动化任务继续运行，`repo list` 仍会列出它并设置了 `hiddenAt`，命名它的命令继续工作。隐藏应用于一个主机的项目副本；当设置在多个主机上时，添加 `--host <host>` 选择哪个副本。在已配对的 Orca 服务器上，设置保存在该服务器上，因此在那里隐藏项目会为连接到它的每个人隐藏。`repo unhide` 或侧边栏底部的隐藏项目列表会再次显示它。

`repo add` 默认为 `--kind git`。使用 `--kind folder` 打开普通目录，包括包含独立 Git 仓库的 repo-tool 根目录，作为没有 Git 工作树或源代码控制的文件夹工作空间。使用 `--environment` 时，使用该 Orca 服务器上的绝对路径。

## 工作树

```bash
orca worktree list --repo id:<repoId> --json
orca worktree ps --json
orca worktree current --json
orca worktree show --worktree active --json
orca worktree create --repo id:<repoId> --name fix-login --json
orca worktree create --name child-task --agent codex --prompt "Investigate the flaky login test" --json
orca worktree set --worktree active --comment "reproduced failure; testing token refresh fix" --json
orca worktree set --worktree active --workspace-status in-review --unread --json
orca worktree rm --worktree id:<worktreeId> --force --json
```

当从 Orca 管理的工作树内部运行 `worktree create` 时，Orca 会在可以推断关系时将新工作树记录为子级。传递 `--parent-worktree active` 来显式指定，或在新工作独立时传递 `--no-parent`。

传递 `--branch DAT-111-fix-login` 自己命名 Git 分支，而不是应用配置的分支前缀。`--name` 仍设置工作空间名称，`--base-branch` 设置起始引用。如果该分支已存在且无法重用，或工作空间路径已被占用，Orca 会向两者附加数字后缀，就像它在新工作空间编辑器中所做的那样，因此 `--name task --branch exact` 可能产生分支 `exact-2`，即使 `exact` 空闲。

`worktree set --unread` 在侧边栏的工作空间上放置未读标记，与代理完成时 Orca 显示的相同；`--read` 清除它。

代理启动标志：

```bash
orca worktree create --name review-api --agent claude --setup run --json
orca worktree create --name quick-check --agent codex --prompt "Summarize the diff" --setup skip --json
orca worktree create --name hidden-setup --setup inherit --json
```

`--agent` 在第一个终端中启动选定的代理。`--prompt` 向该代理发送初始工作。`--setup run|skip|inherit` 控制仓库初始化钩子；`inherit` 遵循仓库策略。

使用现有工作空间元数据关联问题和评审：

```bash
orca worktree create --repo id:<repoId> --name review-task --pr 123 --json
orca worktree create --repo id:<repoId> --name gitlab-task --gitlab-issue 42 --gitlab-mr 77 --json
orca worktree set --worktree active --gitlab-issue '#42' --gitlab-mr '!77' --json
orca worktree set --worktree active --gitlab-issue https://gitlab.example.com/group/project/-/work_items/42 --json
orca worktree set --worktree active --pr null --gitlab-mr null --json
```

`--pr` 是 GitHub pull request 编号。`--gitlab-issue` 接受问题编号或 `#42`；`--gitlab-mr` 接受合并请求编号或 `!77`。数字必须是正的安全整数。GitLab 标志也接受 HTTP(S) 问题或合并请求 URL，包括自托管实例和嵌套组。URL 的主机和项目必须匹配工作空间存储的 GitLab 源上下文或仓库存储的远程。如果该标识缺失或不同，命令会在更新元数据之前失败。URL 不能选择另一个项目、更改检出或获取评审分支。

省略标志会保持其链接不变。在 `set` 时，字面量 `null` 仅清除命名链接；`create` 拒绝 `null`。每个提供商有独立的字段，因此设置 GitLab 问题或合并请求会保留 GitHub 和 Linear 链接。

基于文件夹的仓库可以通过这些命令存储数字链接，但数字不会提供提供商主机或项目。如果没有现有源上下文或存储的远程，粘贴的 GitLab URL 会被拒绝，提供商详情或可点击链接可能不可用。这些标志使用运行时已支持的字段；早于某个字段的旧运行时可能会忽略它，因此写入旧主机后请检查 `worktree show --json`。

### 工作空间清理

```bash
orca workspace cleanup preview --json
orca workspace cleanup run --json
orca workspace cleanup report --json
```

`preview` 显示您的清理规则现在会删除什么，以及每个其他工作空间保留的原因。`run` 现在应用规则：在删除前再次检查每个工作空间，不强制执行任何操作。`report` 列出最近的运行以及下一次运行何时到期。没有规则开启时，不会删除任何内容。当 **删除工作空间时删除代理历史**（设置 > 代理）开启时，`run` 也会从不再存在的工作空间中删除 Orca、Claude Code 和 Codex 聊天记录。规则在 Orca 设置中设置；这些命令从不更改它们。添加 `--environment <id>` 在已配对的服务器上运行它们。

## 端口

```bash
orca ports --json
orca ports --worktree branch:feature/login --json
orca ports --all
```

`ports` 从工作空间运行的主机列出 Orca 绑定到工作空间的监听端口。它默认为包含当前目录的工作空间。每行包含 `port`、`pid`、`processName`、`connectHost`、`protocol`、Orca 如何匹配它（`owner.confidence`：`cwd` 或 `command`），以及当开发服务器在 Orca 终端中打印时的 `advertisedUrl`。`--all` 列出该主机上的每个监听器。原生文件夹工作空间需要 `--all`，因为 Orca 不会将端口绑定到它们。如果设置了 `unavailableReason`，扫描无法在该主机上运行；直接从桌面打开的 SSH 工作空间目前会报告这一点，而托管 Orca 服务器上的工作空间会在该服务器上扫描。

## 引用

一个工作空间可以链接多个评审和问题，包括其仓库之外的来源。

```bash
orca reference list --worktree name:api --json
orca reference add https://github.com/acme/api/pull/5123 https://linear.app/acme/issue/STA-1234 --worktree name:api --json
orca reference remove https://github.com/acme/api/pull/5123 --worktree name:api --json
orca reference remove --key '<key-from-list>' --worktree name:api --json
orca worktree create --name fix --reference https://github.com/acme/api/pull/5123 --reference https://linear.app/acme/issue/STA-1234 --json
orca reference find STA-1234 --json
```

- **写入：** 仅完整 URL；无自定义简写。`remove --key` 支持没有 URL 的旧条目。源未知的旧链接无法匹配确切 URL；存储时仍可搜索原生问题键。重复添加和不存在的移除是空操作。保留不相关的链接和当前选择。没有安全增量合并的旧主机拒绝写入。
- **创建：** 重复 `--reference`；与 `--pr`、`--issue`、`--linear-issue`、`--gitlab-issue` 和 `--gitlab-mr` 不兼容。引用在初始化或代理启动前持久化。
- **查找：** 完整 URL 或原生问题键；拒绝裸数字。键搜索所有匹配的来源。读取存储的元数据，不进行提供商请求或会话搜索。对会话文本使用 `orca search`。
- **作用域：** `--worktree` 选择工作树或文件夹工作空间。查找也接受 `--repo`，加上 `--include-archived` 和 `--limit`（默认 50 个工作空间）。`truncated: true` 表示有更多匹配。远程选择器指执行主机；`current` 仅为本地。
- **输出：** 列表返回带有不透明 `key` 和 `selected` 的 `references`；写入也返回 `changes`。工作树显示/列表/ps 保留 `linkedItems`。查找返回工作空间匹配和带有 `linked`、`liveness` 和可用 `terminal`/`mailbox` 地址的代理。`linked: false` 表示所有权未知；共享工作空间不足以作为证据。

从 `find` 中选择一个代理，然后使用其确切地址：

```bash
orca orchestration send --to '<terminal-from-find>' --subject 'Status' --body 'Status?' --type question
orca orchestration send --to '<mailbox-from-find>' --subject 'Status' --body 'Status?' --type question
```

邮箱是 `dispatch:<id>` 或 `orca_session_id:<id>`；`run:<id>` 指向协调者。查找从不发送消息或分配所有权。从 shell 添加引用不会将该 shell 与代理关联。

## 终端

```bash
orca terminal list --worktree active --json
orca terminal show --terminal <handle> --json
orca terminal read --terminal <handle> --json
orca terminal read --terminal <handle> --screen --json
orca terminal read --terminal <handle> --cursor <cursor> --limit 1000 --json
orca terminal send --terminal <handle> --text "npm test" --enter --json
orca terminal wait --terminal <handle> --for tui-idle --timeout-ms 300000 --json
orca terminal create --worktree active --title "tests" --command "npm test" --json
orca terminal split --terminal <handle> --direction horizontal --command "npm run dev" --json
orca terminal rename --terminal <handle> --title "runner" --json
orca terminal set-pane-title --terminal <handle> --title "reviewer" --json
orca terminal switch --terminal <handle> --json
orca terminal close --terminal <handle> --json
orca terminal close --worktree active --all --json
```

省略 `--terminal` 以定位当前工作树中的活动终端。当您不确定终端在等待什么时，发送前先读取。

关闭会作为移除终端的一部分停止进程。对一个终端使用 `--terminal <handle>`，或对该工作空间中的每个终端（包括其保存的布局和代理恢复记录）使用 `--worktree <selector> --all` 持久关闭。当这些终端稍后应恢复时，使用工作空间休眠。如果执行主机无法确认每个 PTY 已停止，批量关闭会返回失败的 `unverifiable` 结果，而不是声称进程已退出。`terminal stop` 仅为与旧工具兼容而保留。

<Callout title="终端句柄">
  终端句柄是运行时作用域的。如果 Orca 重启或命令报告了过时的终端
  句柄，请运行 `orca terminal list --json` 并重新获取句柄。
</Callout>

`terminal list` 在 Orca 可以验证时报告每个终端的 `executionHostId`，加上带有覆盖和省略主机 ID 的结果级 `hostScope`。将缺失的主机标识或作用域视为 **unverifiable**，而非本地。缺失的终端仅在其执行主机列在 `hostScope.hostIds` 中时才是它已退出的证据。

默认情况下，`terminal read` 返回剥离了终端转义的累积输出流。重绘行的程序因此可能显示为堆叠片段。当您需要当前渲染的帧时使用 `--screen`；响应的 `source` 标识 `stream`、`screen` 或 `screen-unavailable`。屏幕读取没有历史可以翻页，因此 `--screen` 和 `--cursor` 互斥。

对于长输出，使用游标读取。从一次流读取中保存 `nextCursor`，然后用 `--cursor` 传回以仅获取新输出。

## 已安装的代理

```bash
orca agent installed --json
orca agent installed --worktree active
```

列出 Orca 在主机上检测到的可以启动的代理 CLI；在设置 → 代理中关闭的代理被排除，在那里用自定义命令设置的代理被包含。每个 `id` 是 `orca agent launch` 和 `orca worktree create` 中 `--agent` 所接受的值，`default` 标记默认代理。对于正在运行的代理，使用 `agent list`。`--worktree` 检查该工作空间在何处运行代理，例如其 SSH 主机或 WSL 发行版；不会启动已停止的 WSL 发行版来检查。

## 按 ID 管理的代理

```bash
orca agent list --json
orca agent show orca_session_id:3540ecf3-47c3-4876-b825-81bf5d6b3595 --json
orca agent read orca_session_id:3540ecf3-47c3-4876-b825-81bf5d6b3595 --limit 10
orca agent read orca_session_id:3540ecf3-47c3-4876-b825-81bf5d6b3595 --json
```

每个代理、聊天或终端都有一个 Orca 会话 ID (`orca_session_id:<id>`)，即复制 Orca 会话 ID 所复制的内容。`agent list` 列出此主机工作空间中的代理及其 ID；终端代理在首次向 Orca 报告之前不显示任何 ID。聊天在 `/clear` 后保持其 ID；终端代理会获得新 ID。ID 属于运行代理的主机：其他主机上的代理不会被列出，输出会通过列出它们的 `--environment` 来命名这些主机。已完成的终端代理在休眠时保持列为 `done`，即使 Orca 重启也是如此，除非它在执行新操作之前被重新打开并再次休眠。在中途休眠的代理不会被列出。重新打开后，终端代理仅在向 Orca 报告时才重新出现（对于 Codex，在其下一轮次时）。在所有这些情况下，`agent read` 仍可读取它。`agent show` 显示已列出的休眠代理的最新状态以及当工作空间重新打开时它将在何处唤醒。

`agent read` 读取会话，而非屏幕：聊天的历史记录，或终端代理自己的转录。代理无需正在运行，读取也不会启动它。当 Orca 知道其转录在哪里时（已打开，或在工作空间中休眠；在 Windows 上，休眠的 WSL 代理仅在其标签重新打开后），即可读取终端代理。读取可以以状态（`--json` 中的 `state`）开始，该状态是其自己的历史记录所记录的最新轮次：`working` 表示历史记录显示未完成的轮次，因此其回复可能还不在那里，`done` 表示轮次结束且回复在读取中。中途退出的终端代理可能继续读取 `working`；请检查 `orca agent show`。无状态表示未知，从未完成。`agent list` 和 `agent show` 报告 Orca 已知的最新状态，可能不同。要向代理发送消息，使用带有其终端句柄（终端代理）或 `orca_session_id:<id>`（聊天）的 `orca orchestration send`，而非 `orca terminal send`；休眠的终端代理无法接收消息，因此先重新打开其工作空间。

## 聊天

```bash
orca chat rename --session <sessionId> --name "Release notes" --json
orca chat rename --name "Migrate auth"
```

重命名聊天标签，与手动重命名相同。`--session` 接受 `orca agent launch` 打印的 `sessionId`。在聊天内部运行时，它默认为该聊天；使用 `--environment` 时则必需。

## 文件

```bash
orca file open src/App.tsx --worktree active --json
orca file open src/App.tsx --line 42 --column 7 --worktree active --focus --json
orca file diff src/App.tsx --staged --worktree active --json
orca file open-changed --mode both --worktree active --json
```

路径相对于选定的工作树。`--line` 和 `--column` 基于 1；列需要行。在选择文件时应用位置，或使用 `--focus` 立即应用。Markdown 切换到源视图以进行定位。旧主机打开文件时不带定位。`open-changed` 读取 git 状态并以编辑、差异或两种模式打开更改的文件。标签打开时不会改变您当前查看的内容；传递 `--focus` 会将焦点带到它们。

## 内置浏览器

浏览器命令控制 Orca 选定工作树的嵌入式浏览器标签。它们不控制 Chrome、Safari 或 Orca 桌面 UI。

使用快照 → 操作 → 快照循环：

```bash
orca goto --url http://localhost:3000 --worktree active --json
orca snapshot --worktree active --json
orca click --element @e3 --worktree active --json
orca fill --element @e1 --value "user@example.com" --worktree active --json
```

`@e3` 等引用来自 `snapshot`。在导航、标签切换、改变页面的点击以及任何陈旧引用错误之后重新快照。

移动模拟器命令通过 Orca 的工作树作用域桥控制 iOS Simulator 设备。当代理在 Orca 内部操作时使用它们代替原始的 `serve-sim` 或 `simctl`，使生命周期和活动设备状态保持附加在当前工作树。

## Linear

`orca linear` 功能是代理通过 `orca-linear` 技能使用的功能（旧安装名称 `linear-tickets` 仍可用）。优先使用 `--json`。已链接的工作树使用 `--current` 解析。

### 连接

每个 Orca 主机保持自己的 Linear 连接。从 shell 连接无头服务器或 recipe VM，通过 stdin 传递 API 密钥：

```bash
printf %s "$LINEAR_API_KEY" | orca linear connect
printf %s "$LINEAR_API_KEY" | orca linear connect --environment build-vm --json
# PowerShell
$env:LINEAR_API_KEY | orca linear connect
```

### 读取

```bash
orca linear issue --current --full --json
orca linear issue ENG-123 --comments --children --relations --activity --json
orca linear search "auth bug" --workspace all --json
orca linear list --filter assigned --limit 10 --json
orca linear list-issues --team ENG --state started --assignee me --json
orca linear list-issues --query auth --updated-at -P7D --cursor <cursor> --workspace <id> --json
orca linear team list --json
orca linear team states --team ENG --json
orca linear team labels --team ENG --json
orca linear project list --query launch --json
```

`--full` 展开评论、子项、附件、关系和活动。部分标志（`--comments`、`--children`、`--attachments`、`--relations`、`--activity`）可单独使用。

### MCP 样式写入

```bash
# 创建或更新（省略 id/--current 以创建；创建时需要 --team 和 --title）
orca linear save-issue --team ENG --title "Fix auth" --priority high --json
orca linear save-issue ENG-123 --state "In Progress" --assignee me --json
orca linear save-issue --current --project null --due-date null --json

orca linear relation add ENG-1 --related ENG-2 --type blocks --json
orca linear relation remove ENG-1 --related ENG-2 --type related --json
```

`save-issue` 标签 **替换** 完整标签集（Linear MCP `save_issue` 语义）。字面量 `null` 清除受让人、估算、截止日期、项目或父级。

### 字段辅助函数（仍有效）

```bash
orca linear status set --current --to "In Progress" --json
orca linear assignee set --current --me --json
orca linear priority set ENG-123 --to high --json
orca linear estimate set --current --to 3 --json
orca linear due-date set --current --to 2026-08-01 --json
orca linear label add --current --label backend --json
orca linear comment add --current --body "Investigating regression" --json
orca linear attach --current --url https://example.com/repro --title "Repro" --json
orca linear create --title "Flaky login test" --team ENG --priority high --json
```

运行 `orca linear --help` 或 `orca skills get orca-linear` 查看版本匹配的列表。当脚本可能在 Orca 链接的工作树外运行时，传递显式问题 id（例如 `ENG-123`）。

## 账户（主机本地运行时）

在运行 Orca 的无头主机上（`orca serve` 或桌面应用），当远程客户端无法使用 **添加账户**（远程运行时作用域禁用该按钮）时添加管理的 Claude/Codex 账户：

```bash
orca account list
orca account add                 # 默认 Claude
orca account add --agent codex
```

`account add` 在 **此** 主机的终端中运行 `claude login` / `codex login`，然后将捕获的凭据注册到本地运行时。Codex 使用设备授权，因此浏览器可以在另一台机器上完成。在拥有账户的机器上运行这些命令 —— 不是通过仅限客户端的远程会话。

切换新代理启动时使用的已保存账户，针对任何有已保存账户的提供商（Claude、Codex、OpenCode、Devin、Antigravity）：

```bash
orca account list                                               # id、邮箱/标签，以及活动的一个
orca account select --agent claude --account you@example.com    # id、邮箱或标签
orca worktree create --name task --agent claude --prompt "..."
orca account select --agent claude --account system             # 切换回您自己的登录
orca account rm --agent codex --account old@example.com         # 忘记已保存的账户
```

选择应用于在此之后在主机上启动的该提供商的每个代理 —— 与状态栏账户菜单中的切换相同 —— 而非单个工作空间。被多个账户共享的邮箱（在两个组织中一次登录）会被拒绝；改为传递 id。Antigravity 没有 `system` 默认值，`account rm` 从不删除系统凭据。

## 制品

通过登录的 Orca 账户发布 HTML 或 Markdown。查看公共链接不需要登录；创建/列出/更新/删除需要。发布遵循设备上的 **设置 → 制品 → 允许发布公共制品链接**：对于新配置文件默认开启，而在此默认值之前创建的配置文件保留其之前的设置。只有人类可以更改它；没有 CLI 标志可以授予此门禁。`list`、`unshare` 和 `delete` 保持可用，因此您可以在关闭发布后审计或撤销链接。

```bash
orca artifacts share ./report.html --json
orca artifacts share ./notes.md --json
orca artifacts update ./notes.md --json
orca artifacts unshare ./notes.md --json
orca artifacts list --json
orca artifacts list --cursor <cursor> --json
orca artifacts delete <id> --json
```

- 接受的文件：`.html`、`.htm`、`.md`、`.markdown`。
- `share` 将编辑令牌存储在活动 Orca 配置文件中，不打印它。`update` / `unshare` 通过最初共享文件的相同本地路径和配置文件解析。
- `list` 是分页的（`nextCursor` → `--cursor`）。`delete` 接受来自 `list` 的制品 id，不需要原始文件。
- 相对 HTML 资源不上传 —— 共享自包含的 HTML 或绝对资源 URL。
- 被拒绝的发布/更新会失败并返回 `artifact_sharing_disabled`；修复设置而非重试。
- 无头 Orca 服务器没有 Orca 云登录，因此那里的制品和技能共享命令会失败并返回 `sharing_unavailable_on_host`；从桌面应用共享。
- 桌面：打开本地 HTML 或 Markdown 文件并使用 **作为制品共享**，或从侧边栏 **制品** 页面管理链接。

## 代理习惯

- 优先为自动化和代理调用使用 `--json`。
- 优先使用选择器而非解析 UI 标签。
- 发送输入前先读取终端状态，除非下一个输入显而易见。
- 使用工作树注释作为进度检查点。参见 [工作树检查点](/docs/cli/worktree-checkpoints)。
- 使用 [编排](/docs/cli/orchestration) 进行可追踪的多代理分派，而不是临时的终端提示。
