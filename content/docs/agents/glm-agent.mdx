---

import { Callout } from '@/components/docs/prose'

GLM-5.2 可以通过你已经在使用的代理 harness 在 Orca 中运行。在 Claude Code、OpenCode、Cline、Kilo Code、Roo Code、Droid、OpenClaw 或其他 CLI 代理中配置 GLM-5.2，然后从 Orca 的选择器中启动该代理。

Orca 提供隔离的工作树、终端面板、浏览器标签、审阅流程和会话管理。你的 [Z.ai CodePlan 订阅](https://z.ai/subscribe) 和代理配置则提供模型访问权限。

<Callout title="前置条件">
  在代理 harness 中配置 GLM-5.2 之前，你需要一个已激活的 [Z.ai CodePlan 订阅](https://z.ai/subscribe)，并且包含 GLM Coding Plan
  访问权限。OpenAI 兼容的 harness 还需要一个 Z.ai API 密钥。Orca 不包含也不转售 GLM 访问权限。
</Callout>

<Callout title="来源">
  本页记录的是经 Orca 测试的 GLM-5.2 配置。Z.ai 的 [模型指南](https://docs.z.ai/devpack/latest-model)
  可能列出了更新的模型；在替换模型前，请先在此处确认模型名称、上下文限制和 harness 兼容性。
</Callout>

## Claude Code

Claude Code 从 `~/.claude/settings.json` 读取模型覆盖配置。要在 Orca 中使用 GLM-5.2：

1. 打开 `~/.claude/settings.json`。
2. 添加或更新下方的 `env` 块。
3. 重启 Orca 中的 Claude Code 会话，以加载新环境。
4. 在 Claude Code 中运行 `/status` 确认当前活动模型。

```json
{
  "env": {
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "1000000",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "glm-4.5-air",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "glm-5.2[1m]",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "glm-5.2[1m]"
  }
}
```

当你想要使用 GLM-5.2 的 1M 上下文变体时，使用 `[1m]` 后缀，并保持 `CLAUDE_CODE_AUTO_COMPACT_WINDOW` 设为 `1000000`，以便 Claude Code 的压缩窗口与该上下文大小匹配。如果 Claude Code 提示 `[1m]` 模型不存在，请更新 Claude Code 后重试。

对于编码任务，Z.ai 建议使用 `/effort` 将 Claude Code 的 effort 设为 `max`。Claude Code 较低的 effort 设置映射到 GLM-5.2 高 effort，而 `xhigh`、`max` 和 `ultracode` 映射到 GLM-5.2 的 max effort。

## OpenCode、Cline、Kilo Code、Roo Code 和 Droid

对于暴露 OpenAI 兼容 provider 的代理 harness：

1. 在 Orca 内或外打开 harness 设置。
2. 选择 OpenAI 兼容的 provider 选项，或者如果 harness 有 Z.ai provider 选项则选择它。
3. 将基础 URL 设为 `https://api.z.ai/api/coding/paas/v4`。
4. 添加你的 Z.ai API 密钥。
5. 将自定义模型名称设为 `glm-5.2`。
6. 如果 harness 有该字段，将上下文窗口大小设为 `1000000`。
7. 禁用图像支持，除非 harness 专门记录了此 provider 路径下的图像支持。

保存后，从 Orca 的代理选择器中启动该 harness。Orca 会在选定的工作树中运行相同配置好的 CLI。

## OpenClaw

如果 OpenClaw 无法直接从其 provider 模型列表中选择 GLM-5.2，请在 `~/.openclaw/openclaw.json` 中手动添加模型。

将 `glm-5.2` 添加到 `models.providers.zai.models`：

```json
{
  "id": "glm-5.2",
  "name": "GLM-5.2",
  "reasoning": true,
  "input": ["text"],
  "cost": {
    "input": 0,
    "output": 0,
    "cacheRead": 0,
    "cacheWrite": 0
  },
  "contextWindow": 1000000,
  "maxTokens": 131072
}
```

然后设置默认主模型：

```json
{
  "model": {
    "primary": "zai/glm-5.2",
    "fallbacks": ["zai/glm-4.7"]
  }
}
```

并在 `agents.defaults.models` 下添加模型：

```json
{
  "models": {
    "zai/glm-5.2": { "alias": "GLM" },
    "zai/glm-4.7": {}
  }
}
```

重启 OpenClaw 网关：

```bash
openclaw gateway restart
```

然后从 Orca 启动 OpenClaw，或者在 Orca 终端中运行 `openclaw tui` 确认 GLM-5.2 已激活。

关键规则很简单：在 harness 存储 provider/模型设置的任何位置配置 GLM-5.2，然后让 Orca 在正确的工作树中启动该 harness。
