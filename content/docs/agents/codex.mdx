---
title: 在 Orca 中使用 Codex
---

Codex 是 OpenAI 的代理式 CLI。Orca 对 Codex 的集成是应用中最深度的之一 — 用量、热切换和重启都能保留账户身份。

## 初始化

1. 按照 OpenAI 的文档安装 Codex。
2. 在任意终端登录。
3. Orca 从 `~/.codex` 读取账户和凭据。

## 启动

从代理下拉框选择 **Codex**。Orca 以工作树为 `cwd` 启动 `codex`，并通过当前选定的账户路由认证。

## 账户热切换

许多 Codex 用户运行多个账户来最大化 token 配额。Orca 的账户切换器可以在不重新登录或编辑配置的情况下切换活动账户。参见 [热切换 Codex 账户](/docs/agents/codex-hot-swap)。

## 系统默认 vs 额外账户

**系统默认** 使用你真实的 `~/.codex` 登录（与 Orca 外部直接运行 `codex` 使用的同一个 home）。Orca 管理的额外账户在 Orca 的账户数据下有各自独立的 home，因此凭据和发布状态能保持隔离。新的 Codex 启动会跟随活动账户。已打开的 Codex 聊天会在下一条消息发送前切换到新账户；正在运行的终端会话会保持它启动时的 home，直到你重启它。

## 设置 `CODEX_HOME` 的包装脚本

Orca 会在每次启动使用的 home 中安装状态 hooks：**系统默认** 使用 `~/.codex`，额外账户使用该账户自己的 home（以 `CODEX_HOME` 传递）。如果你 `PATH` 上更前面的 `codex` 包装脚本总是导出一个不同的 `CODEX_HOME`，Codex 就会读取到一个 Orca 没有设置过的 home：状态 hooks 永远不会触发，账户切换也无效。要保留自定义 home：

- 让包装脚本尊重已经设置好的 home，这样额外账户才能继续正常工作：

  ```bash
  export CODEX_HOME="${CODEX_HOME:-$HOME/.codex-openai}"
  ```

- 让 `~/.codex` 指向你的自定义 home（先把现有的 `~/.codex` 移走，再执行 `ln -s ~/.codex-openai ~/.codex`），这样系统默认和包装脚本就会读取同一个文件夹。

## 嵌套 Task 子代理

当 Codex 生成 Task 子代理时，Orca 可以在工作树代理列表和 [代理仪表盘](/docs/model/agents-sessions#agent-dashboard) 中把它们显示为父代理下的子行。展开箭头可以查看每个子代理；点击子行会聚焦到父终端（子代理不拥有独立面板）。

## 交接给另一个代理

在代理终端的标题栏或上下文菜单中，选择 **交接给另一个代理**。Orca 会启动一个全新的代理会话（相同或不同的 CLI），并从前一个转录或捕获的上下文中注入一个有限的交接提示。原始会话保持不变 — 这不是 `codex resume`。

## 重启标签

当 Codex 退出时，重启标签会用相同的账户重新启动代理。如果你在会话中途切换了账户，并且想用新账户重启，请先使用账户切换器，再重启。

## 用量与速率限制

Orca 使用你现有的 Codex 登录为活动账户获取 Codex 用量，并在状态栏中展示。参见 [用量与速率限制追踪](/docs/agents/usage-tracking)。

## Windows 上的 Codex (WSL)

在 Windows 上，Orca 可以从主机安装或从 WSL 发行版中运行 Codex。从账户切换器添加一个 WSL 托管的 Codex 账户 — Orca 会在发行版内部创建一个隔离的账户 home（路径为 `~/.local/share/orca/codex-accounts/<id>/home`），将其作为 `\\wsl.localhost\<distro>\...` 路径映射回主机用于认证读取，并通过选定的发行版路由启动、热切换和速率限制获取。如果目标发行版中没有安装 Codex，**添加账户** 对话框会失败，并给出一个可操作的错误消息，告诉你哪个发行版缺少该二进制文件。
