---
title: 代理休眠
description: 让 Orca 暂停空闲的后台代理终端，在你返回时自动恢复它们。
---

import { Callout } from '@/components/docs/prose'

当你打开了几十个工作树时，空闲代理会累加 — 每个都是一个活跃的 PTY，在内存中持有模型会话。代理休眠让 Orca 在它们完成且足够久未被触碰后悄悄停止那些终端，然后当你回到该代理的标签时恢复同一个会话。

<Callout title="实验性功能">
  代理休眠默认关闭。在我们继续优化安全模型的同时，请到
  **设置 → 实验性功能 → 代理休眠** 下开启。
</Callout>

## 哪些会休眠

Orca 仅在**以下所有条件**都满足时才让代理终端休眠：

- 代理处于 **done** 状态 — 它已完成最后一个回合且不在等待输入。
- 其终端标签在屏幕上不可见（活动标签、另一个分屏组中显示的标签，或 Activity 页面上显示的终端）。同一工作树中的其他标签仍然可以休眠。
- 自代理完成以来它没有收到过击键。
- 代理属于 [可恢复会话](/docs/agents/session-history) 之一：Claude、Codex、Gemini、Antigravity、OpenCode、Pi、MiMo Code、Droid、Grok、Devin 或 OMP。
- 空闲时间至少达到配置的空闲窗口（默认 30 分钟）。
- 当前没有移动会话在驱动该终端。
- 没有 [编排](/docs/cli/orchestration) Dispatch 仍未解决（`pending`、`dispatched` 或未知）。运行时确认的 `completed`、`failed` 或 `circuit_broken` 之后才允许休眠。
- 面板上没有活跃的子代理/队友列表（仅 provider 返回 "done" 是不够的，只要子元素还在挂着）。

任何检查未通过的终端会保持运行。每个代理面板会独立检查和休眠，因此完成的面板可以休眠，而同一工作树中的兄弟面板或标签仍在运行。

手动休眠不同：它会同时停止整个工作树。从侧边栏休眠工作树（嵌套有子项时使用 **休眠 → 连同后代**）。参见 [工作树](/docs/model/worktrees)。手动休眠会保留 **完成** 和 **已中断** 的可恢复会话，这样重新打开工作树后仍然能用相同的恢复标志重启 — 它不会因为面板不再"活跃"就抹掉那些会话记录。

## 调整空闲窗口

在 **代理休眠** 开关下，**在空闲多少分钟后休眠** 设置了已完成的后台代理需要等待多久 Orca 才暂停它。

- 默认值：**30 分钟**。
- 范围：**1 分钟** 到 **24 小时**。
- 计时器从代理最后一条 `done` 更新开始；任何击键、新输出或返回代理终端标签都会重置它。

更长的窗口用更少的暂停换取更多的内存节省；更短的窗口暂停更激进，但下次切回来需要恢复。

## 查找休眠的工作树

侧边栏过滤器菜单控制是否显示休眠的工作树。如果你经常隐藏它们，请在 [设置 → 快捷键](/docs/settings) 中为 **切换休眠的工作空间** 分配快捷键，无需打开过滤器菜单就能显示或隐藏它们。

## 恢复

当你切回一个已休眠代理的标签时，Orca 会用它从 [代理会话历史](/docs/agents/session-history) 中使用的相同恢复标志重新启动代理 CLI — `claude --resume <id>`、`codex resume <id>`，等等 — 这样对话、工作目录和 provider 会话就能从离开的地方继续。无需点击任何东西；恢复是将终端重新带到前台过程的一部分。

恢复还会复用 Orca 首次打开代理时捕获的启动命令、参数和私有环境。

如果代理 CLI 因任何原因无法恢复会话（转录被删除、provider 轮换了会话 ID），终端会打开到一个新提示，之前的转录仍可在该代理的会话历史下访问。

## 限制

只有上面列出的可恢复代理会休眠。Cursor CLI、Hermes、Copilot、Trae 和其他不可恢复的终端保持运行。

## 后续步骤

- [代理会话历史](/docs/agents/session-history) — 手动恢复任何过去的会话，包括 Orca 没有让其休眠的那些。
- [热切换 Codex 账户](/docs/agents/codex-hot-swap) — 在不重启会话的情况下切换活跃的 Codex 登录，可与休眠协同工作。
